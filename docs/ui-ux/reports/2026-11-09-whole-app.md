# UI/UX pass: Humble Catalog viewer, whole app, 2026-11-09

## 1. Scope
- Scope: whole app (the web viewer; the CLI is out of scope).
- Audience: "Local searchable catalog of HumbleBundle e-books, audiobooks, and comics" (README.md:3), for a person who catalogues "_your own_ account" (README.md:8) on a desktop browser, plus a read-only phone viewer over LAN (README.md:37). Confirmed by the owner.
- Platforms: web (Flask + vanilla JS), desktop and phone browsers.
- Observed: run in the built-in browser (Chromium) on the demo catalog (`scripts/demo_catalog.py`, port 8099, invented titles), on `main` @ 7947158 after `git pull`. Viewports: 1280×800, 640×400 (≈200% zoom), 375×812. The light and dark themes were set with the app's own toggle.
- Live actions: the owner allowed live humblebundle.com fetches in Bundles, and harmless Tasks jobs. No job was started, because a job started from the demo runs against the real `catalog.db` (F-12).
- Inventory changes since last run: first run.
- Web access: yes. Each standard in §4 was read this run.
- Tools: axe-core could not be injected because the permission check refused loading it from a CDN. The checks were done with page scripts written for this run instead: accessible-name scan, contrast scan using the WCAG formula, target-size scan, and focus checks.

## 2. Summary
The viewer is in good shape for a sighted mouse or keyboard user. It falls short in two places: **write failures are invisible**, and **several custom widgets don't expose their name or state to assistive technology**.

Top problems:
- **F-1**: a reading-status change made while the server is down looks saved, and it is lost without a word. 13 write calls discard the server's answer.
- **F-12**: Tasks jobs started from the demo viewer act on the real catalog, which undermines the project's own privacy rule for screenshots.
- **F-2**: some controls have no accessible name: the per-row status select and the inline editor's fields.
- **F-3**: toggle chips (status filter, key states) and the phone sheet's stars don't say whether they are on.
- **F-4**: none of the 12+ autocomplete fields uses combobox semantics.

Keep these; they already work:
- A visible `:focus-visible` ring everywhere, guarded by a test (style.css:417-424).
- The table's star rating is a proper radiogroup with roving tabindex and per-star labels (catalog.js:192-260). It is the only write that rolls back when the network fails (silently; see F-1).
- The phone edit sheet: it moves focus to Done on open and returns focus to the card on Escape. Its status buttons use `aria-pressed`.
- Explicit states for loading, empty and error in the table, with a persistent live region (index.html:132-145). The bundle buttons show "Checking…" while they work.
- Destructive maintenance actions need a second click to confirm (app.js:118). Restored filters are announced by a banner instead of being applied silently.
- No horizontal page scroll at 375px in any section; wide data tables scroll inside their own container.

## 4. Standards

### A11Y-1: Every control has an accessible name
Rule: Every user interface component has a name that can be programmatically determined (failure F68: a control without one).
Source: https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html
Status: researched 2026-11-09

### A11Y-2: Custom controls expose their state
Rule: States the user can set (pressed, selected, checked, expanded) can be programmatically determined, and changes to them are notified, using WAI-ARIA states (for example `aria-pressed`).
Source: https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html
Status: researched 2026-11-09

### A11Y-3: Autocomplete fields follow the combobox pattern
Rule: The input has `role="combobox"`, `aria-expanded`, `aria-controls` and `aria-autocomplete="list"`; the popup is a `listbox` of `option`s; the highlighted option is tracked with `aria-activedescendant` and `aria-selected`.
Source: https://www.w3.org/WAI/ARIA/apg/patterns/combobox/
Status: researched 2026-11-09

### A11Y-4: Non-text contrast 3:1
Rule: Graphics needed to understand content, and visual indicators of a component's state, have at least 3:1 contrast against adjacent colours. A star rating is the Understanding page's own example.
Source: https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html
Status: researched 2026-11-09

### A11Y-5: Text contrast 4.5:1
Rule: Text has at least 4.5:1 contrast (3:1 for large text). Inactive components are exempt.
Source: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html
Status: researched 2026-11-09

### A11Y-6: Focus order preserves operability
Rule: Focus moves in an order that preserves meaning and operation. When a dialog or editor opened from a control is dismissed, focus returns to that control.
Source: https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html
Status: researched 2026-11-09

### A11Y-7: Status messages are programmatically exposed
Rule: A result or error that appears without moving focus is exposed through a role or property, such as `role="status"` or `role="alert"`, so assistive technology announces it.
Source: https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html
Status: researched 2026-11-09

### A11Y-8: Labels describe purpose
Rule: Headings and labels, where present, describe the topic or purpose of what they label.
Source: https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html
Status: researched 2026-11-09

### A11Y-9: No interactive content inside a button
Rule: An element with `role="button"` contains phrasing content only, "with no interactive content descendants".
Source: https://www.w3.org/TR/html-aria/ (§5, Allowed descendants of ARIA roles)
Status: researched 2026-11-09

### FEEDBACK-1: Visibility of system status
Rule: The design always keeps users informed about what is going on, through appropriate feedback.
Source: https://www.nngroup.com/articles/ten-usability-heuristics/ (#1)
Status: researched 2026-11-09

### CONTENT-1: Errors are reported in plain language, with a way to recover
Rule: Error messages say in plain language what went wrong, pinpoint the problem and suggest a fix.
Source: https://www.nngroup.com/articles/ten-usability-heuristics/ (#9)
Status: researched 2026-11-09

### CONTENT-2: The demo viewer shows only invented data
Rule: Any check that produces an image uses the demo catalog. The demo points every data directory away from the real ones.
Source: CLAUDE.md:16-33 (Privacy, "Images are invisible…"); scripts/demo_catalog.py:252-262
Status: researched 2026-11-09 (project spec)

No standards were decided before this run: `docs/ui-ux/standards.md` does not exist yet.

## 6. Suggested issues

### Surface failed writes instead of showing them as saved
Problem: Status, rating, tags, notes and maintenance actions look saved when the server is down or refuses the change (S1, S1b, D2, S2).
Evidence: F-1
Standard: FEEDBACK-1, CONTENT-1 (https://www.nngroup.com/articles/ten-usability-heuristics/)
Suggested fix: Make `post()` throw on `!resp.ok` and on network failure. At each of the 13 callers, catch it: where the UI already shows the new value (status, rating), put the old one back; where it doesn't (tags, notes, maintenance actions), keep the form as it was so nothing is lost. Then report the failure once, through a shared `role="alert"` line: "Couldn't save — the viewer isn't reachable. Your change was undone." Add a test that drives one caller with a failing fetch.
Impact / effort: high / M

### Run demo-started jobs on the demo database
Problem: Tasks → Run in `demo_catalog.py` acts on the real `catalog.db` (S5).
Evidence: F-12
Standard: CONTENT-2 (CLAUDE.md:16-33)
Suggested fix: Pass the viewer's `db_path` to the child process (a `--db` flag, or an env var the CLI reads), or have `make_app` start the runner with `cwd` set to the demo's temp folder. Add a test that a job started from `make_app` cannot see the real path.
Impact / effort: high / M

### Give the row status select and the inline editor fields names
Problem: Screen readers announce unnamed or context-free fields in the library table and its editor (S1, S1b).
Evidence: F-2, F-10
Standard: A11Y-1, A11Y-8 (https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html, https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html)
Suggested fix: Add `aria-label="Reading status: ${name}"` in `statusSelect()`. Add `aria-label`s to the editor fields ("Series", "Number in series", "Add genre", …). Give × buttons `aria-label="Remove ${tag}"`, and stat jump buttons `aria-label="Show ${row} (${n})"`. This follows the pattern ✎ and ⟳ already use.
Impact / effort: high / M (rated by F-2; F-10 alone is low / S)

### Expose on/off state on toggle chips and sheet stars
Problem: The active state of the status filter, key-state chips and phone-sheet stars is visual only (S1, S3, D2).
Evidence: F-3
Standard: A11Y-2 (https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html)
Suggested fix: Set `aria-pressed` wherever `.on` is toggled. Give `#status-filter` `role="group"`. Make the sheet stars a radiogroup like the table's, or give each one `aria-pressed`.
Impact / effort: high / M

### Keep focus on the row when the inline editor opens or closes
Problem: Keyboard users are thrown to the top of the page after Edit, Save or Cancel (S1b).
Evidence: F-7
Standard: A11Y-6 (https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html)
Suggested fix: After the re-render, focus the first editor field on open, and the row's ✎ button on Save or Cancel. This is the same re-render-then-focus approach `setRating` uses.
Impact / effort: medium / S

### Raise star and badge contrast
Problem: Stars and small badges are below WCAG contrast in both themes (S1, D2).
Evidence: F-5, F-6
Standard: A11Y-4, A11Y-5 (https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html, https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
Suggested fix: Darken `--star` in light theme (for example `#b07800`, or add a dark outline). Set `--border-strong` for empty stars to at least 3:1 on both row colours, or use the outline glyph ☆ in `--muted`. Use dark text on `--badge-info`, and darken `--danger` behind the white badge text.
Impact / effort: medium / S (rated by F-5; F-6 alone is low / S)

### Announce bundle and source-URL results and errors
Problem: Errors and results in Bundles and Maintenance are silent for screen readers, and a stale error lingers (S2, S4).
Evidence: F-9, F-11
Standard: A11Y-7, FEEDBACK-1 (https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html, https://www.nngroup.com/articles/ten-usability-heuristics/)
Suggested fix: Put `role="status"` on `.url-result` and on the bundle report's error line, and `role="alert"` on `.bundle-error`. Clear the old error when a new check or browse starts. On an empty submit, say "Paste a HumbleBundle URL first" next to the field.
Impact / effort: medium / M (rated by F-9; F-11 alone is low / S)

### Take the bundle links out of the phone card's button
Problem: Phone cards are buttons that contain links (S1c).
Evidence: F-8
Standard: A11Y-9 (https://www.w3.org/TR/html-aria/)
Suggested fix: Make the card a plain `<article>` whose title is the `<button>` that opens the sheet. Stretch it with a `::after` overlay so the whole card stays tappable, and keep the links as siblings.
Impact / effort: medium / M

### Use combobox semantics in autocomplete.js
Problem: Autocomplete suggestions are invisible to assistive technology in 12+ fields (S0, S1, S1b, S2).
Evidence: F-4
Standard: A11Y-3 (https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)
Suggested fix: In autocomplete.js, set `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded` and `aria-controls` on the input. Make the list a `listbox` with `option` items that have ids, and track the highlighted one with `aria-activedescendant` and `aria-selected`. Every field uses the same module, so one change covers all of them.
Impact / effort: medium / M

## 9. Ratchets

- How: a pytest that scans `static/*.js` for `await post(` calls whose result is thrown away (not assigned and not inside a `try`). It compares them against a baseline file. - Runs in: the existing `verify` / pytest job.
- Locks in: F-1.

**R-2: accessible names and states in the rendered viewer.**
- Measures: A11Y-1, A11Y-2, A11Y-3, A11Y-4, A11Y-5, A11Y-9.
- How: Playwright is already a dev dependency (`.venv` has 1.61.0), and the viewer smoke test (`scripts/smoke_viewer.py`, tests/test_smoke_viewer.py) already serves the demo. Add `axe-core` from a local npm or pip package (not a CDN) and run it on each of the five `#/` sections at 1280 and 375, in light and dark. Then:
  - fail on any violation not listed in `tests/a11y-baseline.txt`;
  - fail on any baseline line that no longer occurs;
  - fail if a section listed in `shell.js` is not visited;
  - before running axe on a section, assert that it rendered at least one row or card, so an empty page can't pass.
- Baseline today: about 10 entries, an estimate from F-2 to F-6 and F-8 across the sections.
- Runs in: the `verify` job, next to the smoke test.
